# 第二章 阶段一：把需求想清楚（最省时间的一章）

这一章不碰任何技术，但它是全书回报率最高的一章。需求越清楚，后面开发越顺，审核越少被拒。

### 2.1 一句话说清你的小程序

试着填这个空：

> 我的小程序叫______，给______用，帮他们______，他们用完会______。

举例：

> 我的小程序叫"晨读打卡"，给想养成早起阅读习惯的人用，帮他们记录每天读书时长并看到坚持天数，他们用完会每天回来打卡。

如果你填不满这个空，说明想法还太模糊，先想清楚再往下走。

### 2.2 MVP 思维：第一版只做一件事

新手最容易犯的错，是第一版就想做"功能全都有"的产品。结果开发周期拉长，Bug 一堆，审核被拒，热情耗尽。

正确做法：**第一版只做最核心的那一个功能**，其他全部砍掉。

- 想做工具？第一版先做"一个功能能用"，不做设置中心、主题皮肤
- 想做内容？第一版先做"内容列表 + 详情"，不做评论、收藏夹、推荐算法
- 想做电商？（需非个人主体，见 2.3）第一版先做"商品列表 + 下单"，不做会员、优惠券、分销

第一版上线后，根据真实用户反馈再加功能，一点都不迟。

### 2.3 先查规则，再动手：你的想法允许吗

**这是最容易被忽略、代价最大的一步。** 很多人开发了三周，提审时才发现"个人主体不能做这个类目"，全部白干。

动手前，先确认两件事：

1. **你的业务属于哪个类目**（微信后台「设置」-「基本设置」-「服务类目」能看到全部类目库）
2. **你的主体能不能做这个类目**

个人主体能做的类目有限。以下是常见情况（完整清单以微信后台类目库实时显示为准）：

| 个人主体**能做**（常见） | 个人主体**不能做** |
|---|---|
| 工具类（效率、查询、计算、格式转换、记账、日历、天气、备忘录等） | 电商、外卖、二手交易 |
| 生活服务（家政信息、缴费信息查询等） | 社交社区、论坛、评论区互动 |
| 餐饮（菜谱、餐厅点评，**不能交易**） | 在线教育课程、培训 |
| 旅游（攻略、景点信息） | 医疗诊断、问诊开方 |
| 出行信息（公交查询、代驾信息） | 网约车、顺风车 |
| 摄影、音乐（内容展示） | 新闻资讯、时政信息 |
| 健康管理（个人运动记录） | 金融理财、投资建议 |

注意表格里加粗的"不能交易"：**个人主体不能卖东西**（2026 年 9 月起开放了"虚拟商品"收款，详见 3.5 节，但实物交易仍然不行）。

拿不准的类目，把你想做的功能描述发给 AI，让它对照《微信小程序平台开放的服务类目范围》帮你判断，或者直接问微信客服。

### 2.4 写一份"给 AI 看的需求文档"

不用写正式文档，一份清单就够。这份文档有两大用途：**指导开发** + **提审时直接用**。

```text
【小程序需求文档】

1. 一句话定位：给谁用，解决什么问题
2. 第一版功能清单（只列 3-5 个，按重要性排序）
   - 功能 1：……
   - 功能 2：……
3. 页面清单：一共几个页面，每个页面上有什么
4. 数据：需要存什么数据（比如用户信息、打卡记录）
5. 收款：收不收钱？收什么钱（虚拟商品/实物）？
6. 用户登录：需要微信一键登录吗？
7. 其他：有没有要调的硬件、第三方服务？
```

**示例**（待办清单小程序）：

```text
【小程序需求文档】

1. 一句话定位：给事务多的人用，快速记录待办事项并追踪完成情况
2. 第一版功能清单：
   - 添加待办（输入文字，选截止日期）
   - 勾选完成/取消完成
   - 左滑删除（带确认）
   - 按"今天/全部/已完成"筛选
3. 页面：首页（列表+添加按钮）、我的页（统计数字）
4. 数据：每条待办存（内容、截止日期、完成状态、创建时间）
5. 收款：不收钱
6. 登录：不需要，本地就能用
7. 其他：无
```

这份文档后面会反复用：开发时发给 AI，提审时"功能描述"照抄。

### 2.5 本章避坑

- **别跳过类目核查**。先花 20 分钟确认主体和类目，能省三周返工。
- **别追求完美**。第一版丑一点、功能少一点，完全没关系。
- **文档别太长**。三五行比三十行有用，AI 理解简短明确的需求更准。
