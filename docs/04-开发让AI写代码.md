# 第四章 阶段三：开发——让 AI 帮你写代码

从这章开始"做东西"。你的角色从"办事员"切换成"产品经理 + 验收员"。

### 4.1 技术选型：零基础的三条路

| 路线 | 是什么 | 适合谁 | 本指南建议 |
|---|---|---|---|
| **原生小程序** | 微信官方标准写法 | 所有人，尤其零基础 | ✅ **首选**，官方文档最全，AI 训练数据最多 |
| **uni-app / Taro** | 一套代码编译成小程序/App/H5 | 以后想多端发布的人 | 备选。多端有需求再考虑 |
| **低代码平台（微搭等）** | 拖拽组件生成 | 完全不想碰代码的人 | 备选。灵活性差，复杂功能仍要写代码 |

**后端也选一下**：

| 方案 | 是什么 | 适合谁 |
|---|---|---|
| **微信云开发** | 微信官方的"后端套餐"：数据库 + 云函数 + 存储，免运维 | ✅ **零基础首选**，第五章详解 |
| 自建服务器 | 自己买云服务器、配域名、写后端 | 有特定技术需求/后期迁移 |

### 4.2 装好三样东西

1. **微信开发者工具**（稳定版）：`developers.weixin.qq.com/miniprogram/dev/devtools/download.html`，用微信扫码登录
2. **Node.js**（云开发要用）：官网下载安装包，一路下一步（安装时**不要**改安装目录）
3. **一个 AI 编程工具**：Cursor、Claude Code、GitHub Copilot、WorkBuddy 等任选一个（选型对比见[附录二 B1](附录二-AI编程工具开发小程序速查.md)）。使用时选一个固定的项目文件夹当"工作空间"（比如 `D:\my-miniapp`）

> 装 Node.js 的验证方法：打开电脑终端（Windows 是 cmd，Mac 是终端），输入 `node -v` 回车，显示一串 v 开头的版本号就是成功了。

### 4.3 新建项目，开通云开发

**在微信开发者工具里**：

1. 「新建项目」→ 填项目名称 → 选一个**空文件夹**当目录
2. AppID 填你第三章记下的那个（**不能用测试号**，否则云开不了）
3. 后端服务选「小程序·云开发」→ 新建
4. 点工具栏的「云开发」按钮 → 【开通】→ 创建环境：
   - 环境名称随便起（比如 `myapp`）
   - **环境 ID 只能用小写字母、数字和连字符（-）**，起个好记的（比如 `myapp-prod`），待会儿代码里要填
5. 创建完成后会自动弹出云开发控制台，花两分钟熟悉四个板块：**数据库、存储、云函数、监控**

**把项目连上云环境**：打开项目里的 `app.js`，找到这段，把环境 ID 换成你的：

```js
wx.cloud.init({
  env: 'myapp-prod',   // 换成你的环境 ID
  traceUser: true
})
```

### 4.4 怎么跟 AI 提需求

vibe coding 的节奏是：**说一句 → 看结果 → 说下一句**。给你五个实战建议：

**1. 一个任务只说一件事。**
"先做首页：顶部标题 + 待办列表 + 底部添加按钮" 比 "把整个小程序做出来" 效果好十倍。

**2. 把第二章的需求文档喂给它。**
把需求文档上传到对话里，或在对话里 `@` 引用它。AI 会基于文档工作，不会自由发挥。

**3. 描述"长什么样"，别描述"怎么实现"。**
说"点删除时弹一个确认框，防止误删"，不说"调用 wx.showModal 然后 bindtap 触发 remove"。前者是你的工作，后者是 AI 的工作。

**4. 它写完，你验收三件事**：跑起来看看（编译→预览）、功能对不对、页面丑不丑。不满意就直接说人话："标题再大一点""这个按钮放右下角"。

**5. 上下文会断，项目会大。** 单个任务做太久，AI 可能"忘记"早期的约定。对策：让 AI 把关键约定（比如命名规则、页面清单）写进一个 `README.md` 放在项目里，每次新任务让它先读这个文件。

**提示词模板库**见[附录二 B2](附录二-AI编程工具开发小程序速查.md)，拿来即用。

另外，微信官方还发布了一批小程序开发 Skills（虚拟支付接入、云开发集成、开发者工具 CLI 操作等），装上后 AI 能直接调用微信开发者工具的能力，比如自动部署云函数、订阅消息推送——相当于给 AI 配了一双能操作微信官方工具的"手"。清单和安装方法见[附录二 B7](附录二-AI编程工具开发小程序速查.md)。

### 4.5 页面是怎么拼出来的（零基础版）

一个原生小程序项目，你只需要认识这几个文件夹：

```text
你的项目文件夹/
├── pages/            ← 所有页面，一个页面一个文件夹
│   ├── index/        ← 首页
│   │   ├── index.js    ← 页面的"大脑"：数据和逻辑
│   │   ├── index.json  ← 页面的"配置"：标题、用了哪些组件
│   │   ├── index.wxml  ← 页面的"骨架"：按钮、文字、列表长在哪
│   │   └── index.wxss  ← 页面的"妆容"：颜色、大小、间距
│   └── mine/         ← "我的"页，同理四个文件
├── app.js            ← 整个小程序的"总配置"（云环境就在这里连）
├── app.json          ← 小程序的总目录：有哪些页面、窗口长什么样
└── cloudfunctions/   ← 云函数目录（第五章详解）
```

四个文件的分工，用开餐厅比喻：

- **wxml** = 店面装修（桌椅摆哪、菜单贴哪）
- **wxss** = 软装风格（灯光色调、桌布花纹）
- **js** = 店长（记住每桌点了什么，决定什么时候上菜）
- **json** = 门店规章（招牌写什么、营业时间）

**你不需要记住这些**。知道有这几个文件、AI 会改它们，就够了。你的验收动作永远是：编译 → 预览 → 点一遍。

### 4.6 数据库与云函数：数据存哪，逻辑跑哪

小程序的数据和逻辑分两半：

| | 放在哪 | 管什么 | 类比 |
|---|---|---|---|
| **数据库** | 云端（云开发的数据库） | 存数据：用户信息、待办、订单 | 仓库 |
| **云函数** | 云端（云开发里的一段代码） | 跑逻辑：算账、鉴权、调支付 | 后厨 |

**数据库**是"文档型"的：不用提前设计表格，一条记录想存什么字段就存什么字段，很灵活。待办清单项目，就在云开发控制台「数据库」建一个叫 `todos` 的集合（集合=文件夹），每条待办就是里面一张"卡片"。

**云函数**的部署有个铁律，新手必踩：

> **云函数改完必须重新部署才生效！** 在开发者工具里右键云函数文件夹 →「创建并部署：所有文件」。改完不部署，线上跑的还是旧代码，怎么调试都没变化。

含云函数的项目第一次部署前，右键云函数文件夹 →「在终端中打开」→ 输入 `npm install` 回车（下载依赖包），再右键部署。这一步 AI 会提醒你，但它不能替你点右键。

### 4.7 真机预览与自测

点开发者工具工具栏的「预览」→ 生成二维码 → 微信扫码 → 在真机上跑。**模拟器永远有偏差，iOS 和安卓都要试。**

自测清单（每次改版都过一遍）：

- 每个按钮都点了，没白屏、没卡死
- 断网时 app 不崩溃，有"网络开小差"提示
- 手机上从后台切回来，页面状态正常
- 云功能（登录、提交数据）真实跑通，不是空转

### 4.8 代码与文件管理

- **每天备份项目文件夹**：复制一份到移动硬盘或网盘，命名带日期。AI 偶尔会"改坏"，备份是后悔药。
- **大版本留档**：每次提审前，把整个文件夹复制一份命名 `v1.0.0-提审前`。出问题能回退。
- **别把密钥提交到任何公开地方**：AppSecret、AppKey、支付密钥，只存在本地安全处。

### 4.9 常见开发故障与自救

| 症状 | 八成是这原因 | 怎么办 |
|---|---|---|
| 编译报错，红字一片 | 代码语法错 | 把报错信息**整段复制**发给 AI，让它修 |
| 改了代码没变化 | 没保存（Ctrl/Cmd+S）或没编译 | 保存 → 点「编译」 |
| 云函数调用失败 | 没部署，或环境 ID 不对 | 右键云函数重新部署；核对 app.js 里的 env |
| 请求报"不在合法域名" | 走了 http 或域名没配白名单 | 用云开发；或去后台「开发设置」配 HTTPS 域名 |
| 预览二维码扫不了 | 登录开发者工具的微信不是项目成员 | 用管理员/开发者微信扫码登录工具 |
| 上传时代码包超限 | 图片太大、代码太多 | 让 AI 压缩图片、做分包；主包/单分包上限 2MB，分包总和上限 30MB |
