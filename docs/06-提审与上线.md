# 第六章 阶段五：提审与上线

### 6.1 提审前自查清单

逐项打勾，全过了再提交。这份清单能帮你避开八成驳回：

**账号资质**

- [ ] 备案已完成，后台显示"已备案"
- [ ] 服务类目和实际功能一致，该有的资质都上传了
- [ ] 《用户隐私保护指引》已填，且勾选了实际用到的接口类型
- [ ] 名称、简介无极限词、无商业化用语、和实际功能一致

**功能与内容**

- [ ] 每个页面都能打开，无空白页、无"敬请期待"
- [ ] 核心功能在**首页**就能看到（规范要求）
- [ ] 无诱导分享、诱导关注、多级分销、网赚类设计和文案
- [ ] 图片、字体、音乐有商用授权，不碰他人商标和素材
- [ ] 涉 UGC（用户发内容）的，有敏感词过滤和举报入口

**测试**

- [ ] iOS、安卓真机各跑一遍核心流程
- [ ] 断网、弱网不崩溃
- [ ] 有登录功能的话，**提审时附上测试账号**（审核员进不去就会被拒）
- [ ] 第一版功能太少会被判"过于简单"，至少做出完整可用的闭环

**版本**

- [ ] 开发者工具里上传成功，版本号规范（如 1.0.0）
- [ ] 后台「版本管理」-「开发版本」能看到刚上传的版本

### 6.2 提审三步走

1. **上传**：开发者工具点「上传」→ 填版本号和备注 → 确认
2. **设为体验版**：MP 后台「版本管理」→ 开发版本 →「选为体验版」→ 生成体验版二维码 → 拉上你的测试用户（个人主体上限 15 人）真机走一遍
3. **提交审核**：体验版 →「提交审核」→ 填功能页面路径（至少一个）、测试账号（如有）、补充说明 → 提交

审核期间版本状态变为"审核中"。官方口径审核时长**一般 1-7 天**，节假日顺延；金融、医疗、教育等特殊类目可能更长。

**赶时间的三条加急路**（逐年收紧，以后台实际显示为准）：提审时勾选加急选项；符合条件的账号可申请内部加急；2026 年起部分账号在「付费管理」可见付费加急额度（灰度开放中）。

### 6.3 被拒了怎么办

被拒是常态，别慌。按这个顺序处理：

1. **看驳回理由**：MP 后台「通知中心」有具体原因和截图
2. **对号入座**：对照下表修
3. **改完重提**：同一版本改完重新上传提交即可，不额外收费

| 高频驳回原因 | 对策 |
|---|---|
| 类目不符/超个人主体范围 | 换对应类目，或砍掉超范围功能 |
| 功能与描述不符 | 简介、提审说明改得和实际一致 |
| 隐私指引缺失/接口未声明 | 补齐《用户隐私保护指引》 |
| 测试账号无法登录 | 附可用测试账号，或临时关闭登录门槛 |
| 页面打不开/白屏 | 真机复现路径，让 AI 修复 |
| 含诱导分享/违规营销文案 | 删除相关设计和文案 |
| 名称/简介不规范 | 去掉极限词、商业化用语 |
| 功能过于简单/同质化 | 补全核心闭环，做出差异化 |

### 6.4 发布：全量还是灰度

审核通过后，管理员微信会收到通知。去「版本管理」→「审核版本」→【发布】。两种模式：

- **全量发布**：所有用户立即用上新版。适合第一版和小改动
- **分阶段发布（灰度）**：先放给一小部分用户（如 10%），观察几天没问题再全量。适合大改版

**回退**：线上版出严重问题，可在「版本管理」把线上版回退到上一个稳定版本。所以每次提审前留档（4.8 节）很重要。

### 6.5 上线后第一周必做

- 用「预览」和搜索两条路径各打开一次线上版，确认是用户看到的版本
- 盯「监控」错误率 48 小时
- 收集第一批用户反馈，记下来，别急着改——先观察，再规划第一次迭代
- 检查云环境：如果还在用免费环境，倒记 15 天，准备转付费（见 5.3）
